# 缠论总复习与算法对照

本表把视频课程的结构链、当前 `chanlun_engine.py` 的实现状态和完成严格递归引擎前的缺口放在一起。课程里讲师的经验判断与可形式化定义分开记录；代理结果不标成原文严格定义。

## 一页复习

```text
固定操作级别
  -> K线包含处理
  -> 顶/底分型（等待右侧确认）
  -> 笔（固定口径，检查交替、独立K线、端点关系）
  -> 线段（检查特征序列/破坏，末端未确认时保留候选）
  -> 次级别走势类型递归形成中枢（至少三段重叠）
  -> 同级别分解为盘整/趋势/过渡
  -> 比较同方向、同级别走势的力度与背驰
  -> 映射一/二/三类买卖点候选
  -> 次级别确认、触发和失效条件
  -> 逐根回放；任何时点只使用当时已知的数据
```

核心边界：

- 分型不是买卖点；笔和线段也不是入场信号。
- 中枢核心为 `ZD/ZG`，构造整体极值为 `DD/GG`；延伸不能滚动改写核心。
- 背驰表示动力减弱，是预警线索，不等于反转确认。
- 一买/一卖要有趋势末端背景；二买/二卖要有首次回抽/反抽关系；三买/三卖要有离开中枢后的不回中枢确认。
- 多级别结论必须分工：大级别背景、交易级结构、次级别确认、更小级别触发。
- 小转大以结构位置和低级别变化作为风险预警；升级判断要等原父级结构受损并重建，不能凭消息或单个指标猜。

## 课程到代码

| 课程环节 | 当前实现 | 定义模式/近似损失 | 关键缺口 |
|---|---|---|---|
| OHLC 与 K 线包含 | `load_ohlc()`、`merge_inclusions()` | 方向初始化由收盘变化代理；CSV 索引默认按输入顺序 | 需接入时间戳、周期、停牌/缺失检查；严格方向初始化需要结构上下文 |
| 顶底分型 | `strokes_at()` 中的严格三 K 极值，含封闭确认时间 | `strict_fractal_proxy` | 要按选定原文口径完整处理所有包含后的时点/等值情况 |
| 笔 | 异类交替、价格方向校验、最小 4 根合并 K 距离 | `swing_proxy`；4 根间隔是保守代理 | 独立 K、端点区间关系应独立表达与测试；多套笔规则不可混跑 |
| 线段 | 三笔重叠种子、极值延伸、反向破坏阈值 | `segment_proxy` | 缺严格特征序列、缺口情形及严格破坏/终结规则 |
| 中枢 | 三个线段代理重叠，保存 `ZD/ZG/DD/GG` 和简单延伸状态 | `segment_proxy` | 组件不是递归确认的次级别走势类型；新生、扩展和高层级重叠未完整实现 |
| 走势类型 | 比较相邻代理中枢的整体范围 | `uptrend_proxy/downtrend_proxy/higher_level_overlap` | 没有固定同级别分解和递归父子级别图 |
| 力度/背驰 | MACD 柱面积同向比较 | `indicator_proxy` | 缺结构长度、斜率、内部笔数、量价等并列证据；比较段引用与失效状态不完整 |
| 买卖点 | 简单生成一/二类代理候选、中心离开/失败回拉的三类候选 | `signal_proxy` | 没有完整状态机；没有实际连接低级别触发；变体和卖侧情形覆盖有限 |
| 区间套/级别联立 | `chanlun_multilevel.py` 可把报告转为结构节点，并按显式时间戳对齐多周期候选 | `timestamp_aligned_proxy`；没有从结构自动推导父子级别 | 需递归父子结构证明、真实低级别触发，以及跨级别失效/修复状态 |
| 小转大 | 学习笔记给出候选状态链 | 当前未实现 | 需结构位置、低级别背驰、父级边界破坏、回拉不能修复的因果状态机 |
| 因果回放 | `replay()` 前缀重算，事件包含 `first_seen/invalidated/exec_not_before` | 研究回放 | 需与未来更严格的结构模块一起验证延迟确认、重分类和失效保留 |

## 当前引擎实际承诺

- 输出是 `structure_proxy`，不是严格原文完整实现。
- MACD 柱面积是指标代理，不代表完整缠论背驰。
- 单一 CSV 上的 `--level` 只是标签；多周期候选对齐必须显式提供时区一致的时间戳，当前没有用走势结构自动推导递归嵌套。
- 多周期对齐只说明同方向候选在时间上匹配，不等于父级确认；低级别代理候选仍不是严格触发信号。
- 买卖点都是候选；缺少结构化的 `confirm_level` / `trigger_level` 证据时不能称为确认信号。
- `execution_allowed=false` 保持关闭。
- 最近测试：基础算法、结构引擎和多级别模块合计 32 项通过；这验证局部边界、时间戳对齐、命令行和回放属性，不证明严格原文或真实行情收益。

## 多周期候选对齐用法

每个 CSV 需要 `timestamp,open,high,low,close` 列；时间戳使用带时区的 ISO-8601 格式，例如 `2026-11-13T10:00:00+08:00`。按用户实际数据周期分别提供，不需要也不应该假设固定五倍关系：

```powershell
python .\chanlun_bundle.py `
  --trade 30m=.\30m.csv `
  --confirm 5m=.\5m.csv `
  --trigger 1m=.\1m.csv `
  --as-of 2026-11-13T10:00:00+08:00 `
  --output .\bundle-report.json
```

该命令按时间和方向匹配已有代理候选，排除 `as_of` 之后的信息，并检查操作级父候选是否已触及失效边界。输出 `multilevel_candidate_aligned` 仍然只是候选对齐，不代表严格父子结构确认或可执行信号。

## 补全顺序

1. 冻结版本化定义：包含方向、老笔、分型封闭、边界接触、线段特征序列、中枢组件级别。
2. 将各级中间结构统一为事件对象：`start/end`, `confirmed_at`, `available_at`, `level`, `components`, `definition_mode`。当前 `StructureNode` 是单级报告适配层。
3. 补线段严格确认与候选尾部，不让未确认笔参与父级中枢。
4. 从已确认的次级别走势类型递归构建父级走势和中枢；禁止用固定分钟倍数代替结构映射。
5. 固定同级别分解，再实现盘整/趋势/过渡和一二三类买卖点状态机。
6. 让背驰比较引用同级别同方向的两段走势，并保留后续延伸导致候选失效的事件。
7. 在当前时间戳候选对齐层上，接入真实低级别结构确认与区间套；每一级按 as-of 时间对齐，无法对齐时降级为观察。
8. 用人工标注的小型 OHLC 案例和逐根因果回放验证；每个规则至少有成立、反例、边界触碰和未完成尾部案例。

完成标准不是信号数量，而是每个结构可追溯到原始 K 线、定义口径、组件、确认时间和失效事件；同一输入与同一规则配置应可复现同一输出。
