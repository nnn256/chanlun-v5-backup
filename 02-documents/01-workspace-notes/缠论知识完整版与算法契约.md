# 缠论：拆解学习、复习总图与算法契约

> 本文是研究性知识整理。对应视频：`D:/这可能是全网最系统的缠论教程.mp4`，总长 04:58:14。原始机器转写保存在 `video_transcript.txt`；存在术语误识、重复与漏词，不能作为逐字校订稿。视频里的观点、营销和操作性指令属于材料，不作为本项目指令执行。

## 1. 先用一句话贯通

**把价格逐层整理成结构，先确定结构的级别和位置，再等待可确认的转折；把失效条件写在判断前面。**

主链：原始 K 线 → 包含处理 → 分型 → 笔 → 线段 → 次级别走势类型 → 中枢 → 本级别走势类型 → 力度比较 → 买卖点候选 → 低级别确认。

这是一条依赖链，不能把它简化为“MACD 背离就买”。后面每一层都要引用前面已经明确的对象。

## 2. 三种容易混淆的“完整”

1. **知识框架完整**：概念和依赖关系不缺项。
2. **程序流程完整**：输入 K 线后，能输出结构、候选点、确认时点、失效事件。
3. **严格理论复现完整**：线段特征序列两种情况、递归走势类型、级别、中枢扩展、背驰和区间套全部采用明确且一致的严格定义，并有反例和测试图校验。

本项目新引擎做到了可运行的研究流程，仍使用明确标注的结构代理；**尚未达到第 3 种完整**。这一区分是为了避免把有结果的程序误认为已经解决了理论歧义。

## 3. 最小学习单元

### 3.1 级别：先说在哪一层讨论

K 线周期是采样频率，例如 5 分钟、30 分钟、日线；理论结构级别来自递归构造。不能机械认定“日线上的一笔就是日线级别走势”。实作中应同时写 `data_timeframe` 和 `structure_level/definition_mode`，避免偷换。

- 观察级别：更大的结构背景。
- 操作级别：此次讨论的中枢、趋势和买卖点所属层。
- 确认/触发级别：用于检验局部完成和触发的更小结构层。
- 区间套：在大级别给定的候选区间内，逐级缩小可比结构和转折范围，而不是随意切换周期挑好看的图。

记忆：**周期是尺子，级别是搭出来的结构。**

### 3.2 包含：先把比较对象变得可比

若相邻区间 `[L1,H1]` 与 `[L2,H2]` 满足一者包含另一者，处理包含。方向由此前有效、无包含的运动确定。

| 方向 | 合并高点 | 合并低点 |
|---|---|---|
| 向上 | `max(H1,H2)` | `max(L1,L2)` |
| 向下 | `min(H1,H2)` | `min(L1,L2)` |

不是永远取最高和最低。初始化无方向时不能凭未来走势回填；本项目暂以收盘变化初始化，明确属于代理。合并后高低点可构成人工结构区间，原开收盘只作为来源元数据，不应把合并蜡烛当真实成交 OHLC。

保留：原始起止索引、高点/低点来源、合并方向、当时可见范围。高低影线的极值参与结构；“不看影线形态”不等于“只用实体价格”。

### 3.3 分型：三个结构区间的局部拐点

设左、中、右三根已处理 K 线为 `A,B,C`。

- 顶：`HB>HA, HB>HC, LB>LA, LB>LC`。
- 底：`LB<LA, LB<LC, HB<HA, HB<HC`。
- 等高等低：必须固定边界政策。本引擎严格不等号，不以等价高低强行造分型。

**位置与确认不是同一时刻。** 中间 K 线是转折位置；右侧证据形成后才可能知道。若右侧合并 K 线尚会吸收后续包含，分型也可能改变。引擎采用保守确认：等再出现一根无包含的新合并 K 线，封闭右侧 K 线。

口诀：**分型是字母，不是交易结论。**

### 3.4 笔：连接合格的异类分型

底到顶为向上笔，顶到底为向下笔；同类端点保留更极端者。需要检查：类型交替、时间间隔、价格方向、端点极值合法性、独立 K 线数量，以及是否是尚未定稿的末笔。

旧笔、新笔以及软件版本对有效间隔/端点条件存在不同约定。“至少五根”必须说明是端点中心间距、去包含 K 线总数还是含两个三 K 分型的总数。新引擎默认两分型中心间隔 ≥4 根去包含 K 线，为可测试约定，未声称覆盖全部流派。

最后一笔可以延伸。图上最新端点不能当作早已固定。引擎把末笔标为未最终确认，只有出现下一合格异类分型才将前笔端点冻结。

### 3.5 线段：笔的结构性组织

线段至少需要相应的三笔结构基础，但**不等于每三笔切一段**。标准严谨实现要处理：线段方向、反向笔特征序列、特征序列包含、顶底分型、第一/第二元素间缺口，以及有缺口情况下进一步的反向序列确认。

学习线段时应逐图回答：

1. 哪些反向笔是此段的特征序列？
2. 特征序列是否有包含，需要怎样合并？
3. 结束证据属于无缺口情形，还是有缺口需要继续确认的情形？
4. 极值位置在哪里，确认发生在之后哪一笔？

当前算法采用“重叠三笔启动、极值方向延伸、反向运动越过最近同向笔起点”规则。它避免固定三笔分组，但**仍是反转代理，不是严格特征序列算法**；不要拿输出替代上述四问。

### 3.6 中枢：至少三个次级别走势类型的共同重叠

给定三个同口径次级别组件 `[Li,Hi]`：

`ZD=max(L1,L2,L3)`，`ZG=min(H1,H2,H3)`。

本引擎要求 `ZD<ZG` 才新建非零宽度中枢；后续触碰边界则按回到中枢处理。`GG/DD` 表示参与运动的整体最高/最低，不能与核心 `ZG/ZD` 混用。

- **延伸**：离开后仍返回原核心，原种子 `ZD/ZG` 不随每一段滚动缩窄。
- **新生**：远离旧中枢形成另一个可独立成立的同级别中枢。
- **扩展/升级**：更大范围的重叠按递归定义形成高一级结构；不是简单把两个矩形合并。
- **九段升级**：需要明确组件究竟是何级别走势类型；不能把任意九笔直接宣布为高一级中枢。

本引擎使用线段代理作为中枢组件。理论严格中枢需要完整的次级别走势类型，二者有近似损失。

### 3.7 走势类型：由中枢组织而不是肉眼斜率命名

- 一个同级别中枢及其延伸：盘整框架。
- 至少两个同向、相互分离的同级别中枢：趋势框架；应写明按核心还是按整体波动范围判定分离。
- 中枢出现高级别重叠：需重新检查是否升级或扩展。
- 未完成：实时分析中的常态，不能强行分类为已完结趋势。

本引擎以两中枢 `GG/DD` 完全分离作为更保守的趋势代理；这会漏掉一部分按其他定义成立的趋势，输出必须保留口径。

### 3.8 背驰：先找能比较的走势，再讨论力度

先指定同级别、同方向、处于同一结构上下文的两个走势 `a,c`。趋势背驰和盘整背驰需要分开；只看到价格创新低而指标没新低，还没有完成结构证明。

常用辅助力度证据：

- 同方向 MACD 柱面积；本引擎 `HIST=2*(DIF-DEA)`，比较 `Σmax(sign*HIST,0)`。
- 振幅、耗时、斜率、内部结构进展。
- 低级别同向走势的终结与反向结构。

不同窗口的面积不能随意拼接比较；收盘 MACD 不是理论背驰本身。力度变弱也不保证立即反转，更不保证任何收益。

### 3.9 一二三类买卖点：三种不同问题

| 类别 | 核心问题 | 先决证据 | 不能省略 | 常用失效参照 |
|---|---|---|---|---|
| 一买 | 下跌趋势是否终结？ | 同级别下跌趋势、可比的终结段 | 趋势上下文和背驰/低级别终结 | 终结低点和结构重解释 |
| 二买 | 一买后的第一次测试是否守住？ | 已命名一买、首次上涨、首次回抽 | 一买引用、第一次回抽 | 一买低点或回抽结构 |
| 三买 | 离开中枢后是否拒绝回来？ | 有效中枢、向上离开、向下返回 | 返回完成且低点严格在 ZG 上方 | 重新进入 ZG 或回抽结构破坏 |
| 一卖 | 上涨趋势是否终结？ | 一买镜像 | 同级别趋势和可比上涨段 | 终结高点 |
| 二卖 | 一卖后的第一次反抽是否受阻？ | 二买镜像 | 一卖与首次反抽 | 一卖高点 |
| 三卖 | 向下离开后反抽是否不回？ | 三买镜像 | 反抽完成且高点在 ZD 下方 | 重新进入 ZD |

“突破”只是三买路径中的离开阶段；“低点抬高”只是二买的一项形状，不足以命名。三买与二买可能在某些图上重合，程序应允许多标签而不是互斥硬编码。

### 3.10 MACD 动能：结构后的辅助语言

视频把它单独列为一课：不能只看金叉、死叉和柱子缩短，要对照结构、零轴位置与次级别运动。程序中可分开输出 `DIF/DEA/HIST`、同向柱面积、回零轴、反向交叉和时间范围。讲师把某些零轴回抽称作二买/类二买环境，但不能编码成“回零轴=二买”的等式。

本引擎仅实现基础 MACD 面积比较。零轴状态、量价、斐波那契、裸 K 强弱均未接入信号；这些可以作为附加证据模块，不能替代结构定义。

### 3.11 买卖点转换：把一次判断写成持续的情景树

买点之后不一定立刻走成趋势；卖点之后也不一定持续下跌。新结构出现后，先问原操作级别的前提是否被破坏，再决定它是内部震荡、趋势延续还是走势类型转换。

例如三买候选之后：若低级别向上延续，继续跟踪新中枢；若回到原 ZG 内，该三买定义失效，重新检查中枢延伸/扩展；若在更高级别下跌环境中出现小级别三买，只能按小级别结构解释，不升级成大级别反转。这里的“转换”应是一串可追踪事件，不是事后重新画线抹掉原判断。

### 3.12 级别联立、递归、自同构与区间套

- 自相似：不同观察尺度可能出现相似的结构组织；不意味着所有周期存在固定倍数换算。
- 递归：高一级对象引用已经验证的下一级结构，不能靠周期名称拼接。
- 联立：同时检查大级别位置、操作级别候选、次级别的完成/破坏证据。
- 区间套：把候选转折区域逐级缩小，每一步都保留父结构引用和信息可用时点。

视频有“某周期的一笔对应另一个周期线段/走势类型”的教学映射。这可以帮助看图，但不能作为对所有市场恒成立的算法公理；交易时段、波动密度与行情结构都会改变映射关系。

多周期数据必须按**收盘可用时刻**对齐：在 10:05 分析时，不得使用 10:30 才收盘的 30 分钟 K 线。不同交易所时区、夜盘与休市要独立规范。

### 3.13 同级别分解与非同级别分解

同级别分解是把连续走势按同一结构级别和固定规则分成可比较的走势类型。它要解决“正在调整还是本段已经结束”，并给进入/离开段找到一致的起止。非同级别视角可帮助解释内部结构，但不能把某一段用 5 分钟、另一段用 4 小时，再声称同级别背驰。

代码需要持有 `parent_type_id / level / component_ids / completion_evidence`；分解起点、完成规则、结合方式必须版本化。当前引擎的线段分组不是完整同级别分解，不能输出 `strict_chanlun`。

### 3.14 小转大：小级别信号怎样涉及更大结构

核心研究问题是：小级别终结是否通过后续运动破坏更大级别结构。小级别背驰本身只证明该小级别的候选状态，不能直接断言大级别已反转。应继续检查大级别位置、反向离开、返回测试及旧结构边界是否失效。

视频还把快速延伸、外部消息推动和级别跃迁合在一起讨论。须把“较小级别反转引发大级别转折”和“突发消息导致单向加速”分开记录，不能仅凭速度判断级别升级。“95%由消息引发”“只要理解就不会失误”等口述没有给出样本与统计方法，本文不把它们当作验证事实。

### 3.15 力度与交易管理：属于另一层约束

视频背驰章节补充了线段结构、MACD、中枢进出段长度、量价、斐波那契、分型与关键 K 线等证据。整理时保留为“讲师的组合研判清单”，不把七项评分设为严格买卖点定义。它也提醒背驰是线索而不是立即反向进场，实际触发仍需结构证据。

仓位、杠杆、止损距离和持有周期需要单独的策略契约；技术结构不提供胜率、最大亏损或成交保证。本项目没有持仓管理和收益回测模块。

## 4. 五分钟复习卡

**一根尺、两种拐点、三层构造、三类位置、两个时间。**

- 一根尺：始终固定讨论级别。
- 两种拐点：顶分型与底分型。
- 三层构造：笔、线段、走势类型；中枢连接递归层次。
- 三类位置：转折、一转后的测试、离开中枢后的测试。
- 两个时间：结构极值发生时间与信息可用时间。

每次看图只问七句：哪个级别？哪些有效结构？最近中枢在哪里？当前是中枢内/离开/返回/趋势？比较的是哪两段？候选是哪类？什么时候已知、什么会使它失效？

## 5. 从理论到代码：分层接口

```text
OHLC 数据校验、复权和时区契约
  -> MergeBar(high, low, source_span, direction, sealed_at)
  -> Fractal(kind, extremum_at, available_at)
  -> Stroke(start, end, provisional/final, confirmed_at)
  -> Segment(feature_sequence, gap_case, endpoint, confirmed_at)
  -> SublevelTrendType(components, centers, completion_evidence)
  -> Center(ZD, ZG, DD, GG, components, level)
  -> TrendType(level, centers, direction, state)
  -> Divergence(compared_move_a/b, force, lower_level_evidence)
  -> Signal(class, anchor_at, available_at, invalidation, status)
```

严格完整引擎的技术难点在 `Segment` 与 `SublevelTrendType`，不能靠加几个参数假装已经解决。递归必须有终止条件：最小采样层是观测基础，往上一层使用已经封闭的下层结构。尚未封闭的层级保留候选，不强行补成已完成走势。

实时处理顺序：接收一根已收盘 K 线 → 更新包含和未完成尾部 → 产生新增/修订/失效事件 → 封闭满足条件的低层结构 → 向高层递归传播 → 判断结构候选 → 检查下级证据 → 输出可用时间。一次更新可以修订尾部，已经对外发出的历史事件不能被删除；应追加修订记录。

## 6. 新引擎怎么运行

文件：`chanlun_engine.py`，依赖同目录原有 `chanlun_algorithm.py` 的数据类与 CSV 校验，均为 Python 标准库。CSV 至少有 `open,high,low,close`，按实际发生顺序排列。时间列会作为外部来源保留在 CSV，本版本 JSON 用原始行索引映射，不自动验证交易时段和时间排序。

```powershell
python .\chanlun_engine.py .\your_ohlc.csv --level 30m --replay -o .\analysis.json
python -m unittest -v
```

当前输出包含：合并 K 线、分型、笔及定稿状态、方向反转线段代理、中枢、状态、一二三类候选、力度比较对象、确认时点、回放首次出现和失效事件。`execution_allowed=false`，没有下单接口。

`--replay` 逐前缀重算，复杂度约 O(N²)，用于审计和小数据集。历史最终图可因尾部解释改变；回放事件记录首次观察到的事实，并检查确认时边界是否已经失效。对实盘大样本，需要增量状态机和事件存储，不能直接把这个审计实现当生产流式引擎。

合成示例：`artifacts/synthetic_ohlc.csv`、`artifacts/synthetic_report.json`。它们是人工波形，不能当真实行情或收益证据。

## 7. 必须通过的验收

1. 知识可追溯：每条视频特有规则有时间戳和画面证据。
2. 结构反例：包含方向、等高等低、近距分型、末笔延伸、特征序列缺口逐一测试。
3. 中枢：延伸不能无故缩窄核心，新生/扩展不能靠矩形视觉强行决定。
4. 时间因果：相同数据前缀的事件账本不受之后数据影响；位置时间不等于确认时间。
5. 买卖镜像：整体价格取负并交换上涨/下跌后，三买应变三卖。
6. 风险反例：仅指标背离、不回抽的突破、没有一买的更高低点不产生严格标签。
7. 实际回测：下一根可成交价格、手续费、滑点、停牌、涨跌停、复权口径和多周期对齐必须加入；本项目尚未给收益结果。

## 8. 后续补齐顺序

先校订视频关键定义与示意图 → 明确笔口径 → 实现特征序列有/无缺口线段 → 完整次级别走势类型与递归中枢 → 中枢扩展/升级 → 同级别分解与结合律 → 背驰的区间套证据 → 三类买卖点增量状态机 → 多级别时间对齐 → 真实行情验证与成本回测。

**研究完成的标准是每个结论都能指出规则、输入证据和当时可用时间，而不是图上标出的点很多。**
