# 缠论课程复习与可执行算法

> 学习顺序按用户提供的九段视频标题排列。当前环境可确认视频文件存在，但没有可用的字幕、语音转写或视频解码工具；因此本材料是依照课程标题组织的缠论结构化学习稿与可复核算法，不冒充视频逐字笔记。视频原讲例子、术语口径仍需后续用字幕/转写核对。

## 一句话总图

缠论不是“看见形状就下单”，而是先选级别，再把原始 K 线递归整理成结构：**包含处理 → 分型 → 笔 → 线段 → 中枢 → 走势类型 → 力度/背驰 → 买卖点 → 低级别触发 → 失效条件**。任何环节证据不足，结论就降为候选或观察。

## 按课程顺序学习

### 1.《缠论是啥》：先认对象

- **走势**：价格在某一时间级别上的运动，不是指标曲线。
- **级别**：结构递归的尺度。先指定操作级别，再选确认级别与触发级别；不允许事后混用不同周期来证明信号。
- **走势类型**：趋势或盘整。趋势由同级别、同方向的走势结构构成；盘整围绕中枢反复波动。
- **中枢**：至少三个连续次级别走势类型的重叠区。边界常记为 `zg`（重叠区上沿）、`zd`（下沿），扩展范围另记 `gg/dd`。
- **买卖点**：结构位置的分类，不等同于 MACD 金叉、超买超卖或一次突破。

记忆口诀：**先级别，后结构；先中枢，后趋势；先比较，后背驰；先失效，后动作。**

### 2.《K线合并》：去除包含造成的假拐点

相邻两根 K 线若一根的高低范围完全包含另一根（包含或被包含），先合并再找分型。向上时取更高高点与更高低点；向下时取更低高点与更低低点。方向要由已知走势确定；方向未知时不能假装唯一，需标记不确定或采用明确的代理规则。

算法注意：合并会改变可见 K 线数量，必须保留每根合并 K 线覆盖的原始索引，避免信号时间回填到尚未发生的位置。

### 3.《顶底分型教学》：局部结构拐点

对完成包含处理的三根相邻 K 线：中间一根高点和低点都高于两侧，为顶分型；中间一根高点和低点都低于两侧，为底分型。中间 K 线出现后还需等右侧 K 线收完，分型才可确认。

分型只是结构原子，不是买点/卖点。连续同类分型需保留更极端者；顶底交替、时间间隔和有效性规则要按采用的原文/课程口径固定下来。

### 4.《笔教学》：连接相邻异类分型

笔连接一个有效底分型与其后的有效顶分型，或反向连接。它要求分型异类、端点顺序正确、端点间满足最小间隔，并且没有被同类更极端分型替代。

“最少几根 K 线”在不同版本和软件实现中常出现口径差异。代码必须把参数显式配置并标注定义模式；不能用某个参数结果宣称是所有体系共同的唯一笔。

### 5.《第五课缠论线段》：由笔递归成更高结构

线段不是简单“每三笔拼一段”。严格线段判定依赖特征序列、缺口、特征序列分型及破坏/确认规则；不同课程可能采用不同简化讲法。学习时应能回答：线段从哪里起、哪一条特征序列证明它被破坏、何时才确认结束。

本项目代码当前只提供 `segment_proxy`：按连续三笔分组供实验和回测原型使用。它不是严格线段算法，不能用于声称复现了视频中的线段判定。

### 6.《第六课缠论中枢》：重叠是核心

严格定义以至少三个连续次级别走势类型的重叠为基础。若三个组件的区间为 `[low_i, high_i]`，则重叠区可写为 `zd = max(low_i)`、`zg = min(high_i)`；`zd <= zg` 才有交集。需沿递归结构继续检查中枢延伸、新生、扩展，以及离开后是否回到中枢。

延伸：同级别运动继续回到或重叠原中枢。扩展：原本看似分离的结构在更高级别形成重叠。一次越过边界不自动等于趋势已经成立。

代码中的中心是连续笔区间重叠代理，和严格“次级别走势类型重叠”不是同一件事。

### 7.《第七课走势类型》：趋势与盘整由中枢关系刻画

- **盘整**：围绕一个中枢来回运动，可能发生延伸。
- **趋势**：同方向的同级别结构持续发展，并通过中枢之间的位置关系确认；不能只用均线斜率定义。
- **转折/过渡**：旧趋势结束后，新趋势尚未确认的状态。

实作时给结构标状态（例如 `center_oscillation`、`center_extension`、`center_breakout`、`uptrend`、`downtrend`、`transition_zhongyin`、`untradable_unclear`），不要只输出“涨/跌”。

### 8.《缠论背驰完整版》：先找可比的同级别走势

背驰不是“价格创新高但 MACD 没创新高”一句话。先明确比较对象：同一趋势中、同方向、同级别、由中枢分隔的两段走势；再比较力度证据，如走势长度/斜率、MACD 面积与零轴关系、成交/跟随情况，以及低级别反向结构是否破坏。

指标背离仅是力度证据之一。缺少可比结构时只能称指标代理或类背驰观察，不能直接推出一买/一卖。更小级别的背驰也不能未经区间套/递归确认就升级为大级别反转。

### 9.《缠论最后一课：买卖点》：结构位置 + 低级别触发

- **一买/一卖**：下跌/上涨趋势中，趋势背驰后的潜在转折点。必须给出前一同级别趋势、同向走势比较和失效条件。
- **二买/二卖**：一买/一卖后的第一次回抽/反抽测试。不能只凭“低点抬高/高点降低”命名，需引用一买/一卖上下文和测试关系。
- **三买/三卖**：离开中枢后回拉/反抽不重新进入中枢的结构确认。只突破、还没回拉验证时是候选，不是确认。
- 每个点都记录 `依据、触发、失效、下一观察点`，并写清 `trade_level / confirm_level / trigger_level`。

## 简化复习卡

1. 先定级别：没有级别就没有有效买卖点。
2. 先整理 K 线：处理包含，保留原始索引和确认时间。
3. 结构递归：分型 → 笔 → 线段 → 中枢 → 走势类型。
4. 背驰要比同级别、同方向、可命名的两段走势。
5. 一二三类点各有上下文，突破本身不是三买/三卖。
6. 小级别触发不能冒充大级别确认；指标只作过滤证据。
7. 结论先写失效点；结构缺项就降级为候选/观察。

## 当前算法实现

入口：[chanlun_algorithm.py](chanlun_algorithm.py)。输入 CSV 至少包含 `open,high,low,close` 四列（大小写不敏感），运行：

```powershell
python .\chanlun_algorithm.py .\your_ohlc.csv --output .\analysis.json
```

实现内容：CSV 校验、方向依赖的包含合并、三 K 线分型确认时间、异类交替笔、固定三笔线段代理、三笔区间重叠中枢代理、简化状态分类、价格振幅背驰代理、未确认的三买/三卖候选，以及定义模式/近似损失/不可执行标记。

这是第一版可运行研究算法，不是完整严格原文引擎。当前缺少严格线段特征序列规则、递归次级别走势类型中枢、基于力度多维比较的背驰与完整一二三类买卖点状态机。补齐这些部分前，输出 `structure_completeness=partial_proxy`、`execution_allowed=false` 是有意的质量门禁。

## 验收方法

运行：

```powershell
python -m unittest -v
```

有行情 CSV 后，应先核对时区、复权、缺失 K 线、周期与 CSV 排序，再检查 JSON 中的 `confirmed_at`、组件索引和 `definition_mode`。没有数据时不要声称实盘验证或回测结论。
