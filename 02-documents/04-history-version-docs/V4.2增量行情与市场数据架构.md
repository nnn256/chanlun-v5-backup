# V4.2.2 增量行情与市场数据架构

## 实时计算

冷启动按股票、周期读取供应商可取的完整闭合K线一次，逐根装入固定 MIT chan.py 会话。首次和每128根新K线生成一次HMAC认证的白名单对象图检查点，其间每根新闭合K只写一条追加式HMAC日志。内存命中使用`session_reused`状态，只请求最近64根行情；同一进程/检查点恢复不会重新下载或重算已封存历史。检查点恢复使用迭代对象图编码，不使用Python pickle；仅允许固定引擎白名单类。V4.2旧JSON检查点会在迁移时重放一次并保存为新格式。

热更新只取最近64根原始行情，和会话末端作时间/OHLCV逐根比对。已经存在且内容相同的旧K线跳过；新闭合K线按顺序一次追加；形成中的K线只用于绘图，不进入确认结构。每周完整核对上游时间戳集合和OHLCV；发现修订、插入/删除历史或尾部无重叠时，记下原因并重建会话。周审计结果写回检查点，避免无新K时重复全历史下载。坏数据、旧源响应或行情请求失败不会覆盖最后一个有效检查点。追加日志最多128根或16MiB后折叠为新检查点。图表仍返回全历史供缩放查看；这会占用更多响应带宽，但不会重新计算结构。

Python端固定引擎在处理完整前缀时同时维护线段树极值索引，历史信号失效状态查询用区间极值搜索，不必逐根重扫整个历史。图表仍返回全历史供缩放查看，但结构状态由驻留引擎维护。

## 修复的实时路径问题

- 内存命中以前被误判为“未恢复”，导致每次15秒刷新重新请求完整历史。现在把`session_reused`与“从磁盘恢复”分开；新K仅请求尾部，深历史审计按周期执行。
- 全历史周审计在无价格变化时只更新了内存时间，进程重启后会立刻重复审计。现在审计时间持久化。
- 异步全市场扫描以前用扫描启动时刻截断较晚收到的K线，再用更晚快照的端点索引旧前缀。现在每根信号使用报告自身截止点，并检查端点与依据索引。
- 结构信号被边界报价触发时，记录为“报价越界，待闭合K确认”；闭合K失效保留为`invalidated`，不误记为普通`withdrawn`。
- 网页实时查询和全市场监控可能同时读取同一驻留会话；两条路径现共用代码/周期锁，并在锁内生成独立报告快照，避免报告截止点与输入前缀跨时点错配。
- 指数接口最多重试一次且单次超时8秒；最新K时间标签按请求时刻判断是否仍在形成。未收盘日K不标成已闭合，成交量/金额原值单位不明时也不伪称已换算。

## 验证口径

- 固定种子 20261113 随机选两只真实沪深京股票，截止实际最新闭合K线。
- 对每股4个历史前缀，将增量会话与固定引擎全量前缀重算的笔、线段、中枢、信号、观测事件和独立几何复核逐项比较。
- 本次实测：上证603052 993根；深证300707 2208根；8/8前缀完全一致。
- 当前Python 3.14开发机实测：2,208根日K构建固定引擎1.334秒，HMAC对象图压缩检查点768,328字节；检查点恢复0.289秒且不调用历史`append`；热追加一根1.353毫秒。首次加载仍随历史长度增长；这些单机测试耗时不保证其他机器/周期。
- 增量快照随机真实样本仍为上证603052 993根、深证300707 2,208根；每股4个历史前缀，8/8与同一固定引擎全量前缀结果逐字段匹配。
- 全仓库测试：328项通过。另实际请求本地TDX `/api/index`，六个指数均成功，最新闭合日K为2026-11-12；Eastmoney行业请求返回HTTP 502，页面展示错误详情并隐藏空数据表，不会补造板块数值。
- 精确匹配仅证明新旧执行路径在同一锁定引擎和规则上等价，不证明该规则与所有缠论原著解释完全等价，也不是买卖信号胜率或收益证明。

## 市场源

股票日线/分钟K线与指数K线使用本地 tdx-api。界面提供上证、深成指、创业板、沪深300、中证500、中证1000的日线/30分/5分快照和来源时间；指数K行保留成交量、成交额的上游原始值及单位未标准化标记，盘中计划收盘时间会显示为形成中。

行业强弱用单独的 Eastmoney 行业板块HTTP适配器，缓存120秒；接口失败时展示不可用/陈旧状态、HTTP错误和本地接收时间，不补造板块数值。供应商没有在此适配器响应中提供可用的行情快照时间，所以接收时间不代表成交时间。本次开发机请求收到HTTP 502，行业数据仍待可访问Eastmoney网络环境实测；当前适配是已实现但本机未证实可用。详细上游取舍与限制见 DATA_SOURCES_REVIEW_20261113.md。

你列出的代码仓库按职责复核后：

- oficcejo/tdx-api 是当前已有的Go行情服务，继续用作A股K线及指数源。
- injoyai/tdx 是该类TDX协议客户端底层；bensema/gotdx、clong365/easy_tdx、aeroxw/easy_tdx_max 是另一个可选的TDX客户端方向，和已运行服务重叠，本次不再叠加第二套客户端。
- akfamily/akshare 汇集多类金融源，也提供行业板块适配；当前构建环境没有安装AkShare，为避免桌面EXE引入庞大的运行依赖，本次将行业源保持为独立HTTP适配器。
- chanzain/eastmoney-stock-system、roiding/shadowflow 与行业/板块数据流程有关，可供后续在Eastmoney不可达时评估离线缓存、历史板块成员和盘中采集。
- jing2uo/tdx2db 面向历史行情入库，适合历史仓库，不解决当前热更新路径。
- acb6102/opentdx 在本次公开README读取时未取得可核对内容，未纳入运行依赖。
- global-stock-data 主要面向美国股票数据，不作为A股市场源；Vibe-Research 是更完整投研工作台，zhangxiangliang/stock-api 是多市场API封装，均未替换当前算法引擎。

## 运行边界

桌面任务数据库不会随本次版本升级覆盖。更新规则不会触发全市场离线回放；随机股票验证写入独立测试结果。全历史首次载入仍然不可避免，后续正常监控才走尾部增量。历史被供应商修订、服务器漏过的分钟窗口或检查点损坏时会显示重建/校验状态。
