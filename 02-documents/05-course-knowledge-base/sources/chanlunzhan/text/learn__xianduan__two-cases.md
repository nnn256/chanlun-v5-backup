# 第一种情况与第二种情况

判断一个特征序列分型属于第一种还是第二种情况，并说出两者的处理差异。

上一课我们得到了[特征序列](https://chanlunzhan.com/glossary/tezhengxulie)上的[分型](https://chanlunzhan.com/glossary/fenxing)——[线段](https://chanlunzhan.com/glossary/xianduan)结束的候选点。
这一课判定它算不算数。

## 分岔点：有没有缺口

看特征序列分型的第一个元素和第二个元素之间（顶分型就是第一、第二根伪 [K 线](https://chanlunzhan.com/glossary/kline)）
有没有留下空隙。

- 没有缺口 → [第一种情况](https://chanlunzhan.com/glossary/diyizhongqingkuang)

- 有缺口 → [第二种情况](https://chanlunzhan.com/glossary/dierzhongqingkuang)

所谓缺口，就是前一个元素的区间和后一个元素的区间完全不重叠。
对向上线段的顶分型来说，就是第二个元素的低点高于第一个元素的高点。

为什么缺口这么重要

缺口意味着回撤行为发生了跳跃式的变化，而不是渐变。

没有缺口时，回撤是连续加深的，特征序列分型一旦成立，说明[趋势](https://chanlunzhan.com/glossary/qushi)的推进
已经被回撤吃掉，线段结束的证据是充分的。

有缺口时，情况暧昧：跳跃可能是真的转折，也可能只是一次急促的
过渡，后面还会回来继续原来的方向。证据不充分，所以需要额外的确认。

## 第一种情况：分型成立即结束

特征序列分型没有缺口时，规则很简单：

分型成立，线段就在分型的顶点（或底点）处结束。

新的线段从这里开始，方向反转。不需要额外确认。

这是最干净的情况，实际数据里也最常见。

## 第二种情况：需要反向确认

有缺口时，分型本身不足以结束线段。还需要一个额外条件：

从分型之后开始，反方向的特征序列也要形成一个分型。

具体说：一个向上线段，特征序列出现了带缺口的顶分型。这时候要转过来看——
把从这个候选转折点之后的走势当作一个向下线段，取它的特征序列（也就是向上的[笔](https://chanlunzhan.com/glossary/bi)），
看它有没有形成底分型。

- 形成了 → 原来的向上线段确实在候选点结束

- 没形成，走势又创了新高 → 候选点作废，原线段继续

这就是线段最烧脑的地方

第二种情况要求你同时维护两个方向的特征序列：一个用来找候选点，
一个用来确认候选点。

而在确认还没完成的时候，走势可能又创新高，让候选点作废——
这时候刚才为确认建立的那个反向特征序列也要全部丢掉，重新开始。

实现上这就是「取消与回收」，最后一课会专门讲。

## 一个记忆框架

不要背规则，理解这一句就够：

缺口 = 证据不足 = 需要补一次反向确认。

第一种情况证据充分，直接结案。第二种情况证据不足，要求补证。
所有细则都是从这一句推出来的。

## 两种情况的比例

在真实的 A 股日线数据里，第一种情况占绝大多数，第二种情况大约占两成左右
（具体比例随标的和时段变化很大）。

这个比例有个实际含义：如果你只学第一种情况，八成的时候是对的。
这也解释了为什么很多简化实现只处理第一种情况——它们在大部分时候看起来是对的，
只在关键的转折处出错。而关键转折恰恰是最重要的地方。

## 为什么不同软件画的线段不一样

到这里你应该能理解[口径分歧](https://chanlunzhan.com/glossary/koujingfenqi)的来源了。至少有三个地方可以有不同选择：

- 缺口的判定是否包含边界相等的情况

- 反向确认要求「形成分型」还是「形成完整的[次级别](https://chanlunzhan.com/glossary/cijibie)走势」

- 候选点作废时，已经建立的结构怎么回收

原文对这三点的表述都不是完全封闭的。不同实现者的选择不同，画出来自然不同。

本站的选择

本站算法：缺口判定用严格不重叠（边界相等不算缺口）；
反向确认要求特征序列形成分型；回收采用完整回退。

这套口径通过了 [第 81 课《图例、更正及分型、走势类型的哲学本质》](https://chanlunzhan.com/108/81) 的官方图例测试。但请记住这只是一种自洽的实现，
不是唯一正确答案。

## 这一课的要点

- 看特征序列分型的第一、第二个元素之间有没有缺口

- 无缺口 = 第一种情况 = 分型成立即结束线段

- 有缺口 = 第二种情况 = 需要反方向特征序列也形成分型来确认

- 记忆框架：缺口 = 证据不足 = 补一次反向确认

- 只处理第一种情况的实现，在八成时候看起来对，在关键转折处出错
