# 缠论中枢画线公式图解：区间计算与延伸规则

**缠论中枢画线公式怎样计算？**在 Struct Guide 缠论助手（以下简称插件）中，先取连续三条已确认线段各自覆盖的原始 K 线实际最高价 H1、H2、H3 和最低价 L1、L2、L3，再计算共同区间：

text

```text
中枢上沿 ZG = min(H1, H2, H3)
中枢下沿 ZD = max(L1, L2, L3)
ZG > ZD 时，共同区间为 [ZD, ZG]
```

例如三段实际范围依次为 [10, 18]、[12, 18]、[12, 20]，上沿为18，下沿为12，共同区间是 [12, 18]。[数字与图例](https://www.structguide.com/concept/central-zone#用-12-18-的例子核对)在下方展开。

**算出共同区间，还不等于一定画出矩形。**本页说明插件怎样[取实际范围](https://www.structguide.com/concept/central-zone#definition)、[选择成员](https://www.structguide.com/concept/central-zone#members)及[检查延伸](https://www.structguide.com/concept/central-zone#extension)；不能只拿连接端点或三条笔代入算式。线段本身怎样画，见[线段规则](https://www.structguide.com/concept/segment)。

如果你找的是可导入客户端的中枢画线公式源码，可查看[通达信电脑版近似公式下载](https://www.structguide.com/faq/tongdaxin-approx-chanlun-formula#download)或[文华财经 WH6 近似公式下载](https://www.structguide.com/wenhua-chanlun-auto-drawing#download)。两份源码均包含中枢绘制，具体近似规则以各下载页说明为准，与本页的网页插件实现有区别。

## 1. 中枢画线公式：取三条已确认线段的共同范围

插件从连续三条已确认线段里，找它们实际覆盖范围的共同部分。待确认线段要先等，既不能放进最初三段，也不能用来确认后面是否停止延伸。

### 1.1 每条线段的范围怎样取？

先看这一段经过的所有原始 K 线，包括连接端点所在的 K 线，取实际最高价和最低价。不能只拿连线两头的价格：端点一样，中途柱子的极值不同，这一段的范围也可能不同。

三段各取一个最高价 H1、H2、H3，一个最低价 L1、L2、L3。边框就这样算：

| 区间边界 | 计算方式 |
| --- | --- |
| 上沿 ZG | min(H1, H2, H3) |
| 下沿 ZD | max(L1, L2, L3) |
| 输出条件 | ZG 严格大于 ZD |

### 1.2 用 [12, 18] 的例子核对

看下图的三条已确认线段：10到18、18到12、12到20。为了只看算式，这组例子假定每段原始 K 线的实际极值正好就在连接端点上，所以范围可以直接写成：

| 线段 | 端点价格 | 实际覆盖范围 |
| --- | --- | --- |
| 第1段 | 10 → 18 | [10, 18] |
| 第2段 | 18 → 12 | [12, 18] |
| 第3段 | 12 → 20 | [12, 20] |

上沿 ZG = min(18, 18, 20) = 18，下沿 ZD = max(10, 12, 12) = 12。18 > 12，这三段共同经过的价格就是 [12, 18]。范围算好了，还要看它们能否作为这个矩形的成员，见[第三节](https://www.structguide.com/concept/central-zone#members)。

## 2. 上下沿为什么不随后续极值扩大？

先记住这个框：下沿12，上沿18。后面线段即使走得更宽，只要最初三段和它们实际覆盖的范围没变，12和18就不改。

插件会把最初算出的 ZG、ZD 留下来。后面继续接入线段时，主要更新哪些段属于这个框、框要画到什么时间，不拿后来的极值直接改上下沿。

看边框时，可以分开看：

- 上下两条边：由最初三段的实际范围算出，管价格。

- 左右两条边：跟着最终采用的成员范围走，管时间。仅知道12和18，还不知道这个框应该画多长。

后面走到框外时，插件会按[延伸规则](https://www.structguide.com/concept/central-zone#extension)继续判断返回、停止或寻找新窗口。如果最初三段换了，或者历史数据改变了它们的实际范围，就需要重新算上下沿。

## 3. 为什么三条线重叠，还不一定画出矩形？

三段有共同区间后，还要看看它们和前一个矩形怎样接。插件会保留下面这些成员限制：

- 相邻独立中枢之间保留完整连接段，该连接段不同时计入两侧成员。

- 形成旧中枢的第三条线段，不能复用为独立连接段。

- 插件根据新候选区间与前一区间的位置关系，核对初始三段的方向排列。

| 新候选区间与前一区间的关系 | 初始三段的方向要求 |
| --- | --- |
| 新区间下沿严格高于前一区间上沿，即整体在上方 | 下、上、下 |
| 新区间上沿严格低于前一区间下沿，即整体在下方 | 上、下、上 |

先比较两个矩形区间谁在上、谁在下，再选表中要求的三段排列。这里的上、下指连线方向，插件不会为了满足排列要求去挪线段端点。

前面没有矩形可参照，或两个区间的位置关系不能确定表中要求时，就不会只凭一条连接段强行指定方向。成员条件没过，插件把检查窗口往后移，继续找完整的三段，不会切开线段来凑。

所以，图上三条线看着交叠却没画框，可以先看它们是否都已确认，再看实际范围有没有满足 ZG > ZD，最后查成员归属。

## 4. 延伸怎样检查，何时寻找新矩形？

### 4.1 先区分 L0、L1 与公式中的低点记号

下面的图用 L0 记越界线段，L1 记紧接着它、首尾相连的反向线段。这里 L1 是一整段；前面算式中的 L1、L2、L3 只是最低价记号，读的时候留意一下。

最初三段组成矩形以后，再往后找一条完整、已确认的 L0：它向上时，实际最高价要高于 ZG；它向下时，实际最低价要低于 ZD。整段不用都留在框外，中途的实际极值越过边界，也会进入检查。初始三段中的第三段不会再拿来充当 L0。

有了 L0，再等紧接着的反向 L1。L1 还没出现、尚未确认，或没有接在 L0 末端，就还没到可以停止原矩形延伸的时候。

### 4.2 L1 相对区间的四种位置

先看 L0 向上的情况：接下来要看 L1 的实际最低价落在哪。L0 向下时，反过来看 L1 的实际最高价。

| L1 的位置关系 | 向上 L0：核对 L1 最低价 | 向下 L0：核对 L1 最高价 | 插件处理 |
| --- | --- | --- | --- |
| 未返回 | 最低价 > ZG | 最高价 < ZD | L1 已确认且首尾连接时，停止原区间延伸 |
| 恰好触边 | 最低价 = ZG | 最高价 = ZD | 按返回处理，可计入原矩形成员 |
| 进入区间 | ZD ≤ 最低价 < ZG | ZD < 最高价 ≤ ZG | 返回段可计入原矩形成员，继续检查后续线段 |
| 穿过另一边界 | 最低价 < ZD | 最高价 > ZG | 原候选失效，把 L1 作为反方向越界段继续检查 |

表里把“刚好触边”单独列出来：等于边界时也算返回。比较前，程序会先按小数精度归一化，屏幕标签显示得一样，不一定就能直接当成相等。

下面仍用 [12, 18] 这个框，省略最初三段，只看后来接上的 L0、L1。灰线 L0 向上，蓝线 L1 向下且已经确认。这组图假定蓝线的实际最低价就在终点，所以可以直接拿20、18、15、10对照；真实图表里仍要看整段覆盖的原始 K 线。

### 4.3 返回、停止延伸与新矩形如何衔接？

L1 触边或回到区间里，就把返回段放进成员检查，之后仍在区间内的段也可继续加入。如果 L1 一路穿过另一边，插件会把它当成反方向的越界段，继续往后查。

如果 L1 已确认、又没有返回原区间，旧框就停止延伸。从 L1 所在位置开始，插件再找后面的三段窗口。停下旧框之后，还得等新的一组条件满足：三条已确认线段、有宽度的共同区间、成员归属，缺哪一项都暂时不画新框。

旧框画到哪里，要看最终有哪些成员。L0 留作两个框之间的独立连接段，不重复塞进两侧。因此，框的右边缘可能在前面，后面的 L1 才提供停止依据。

延伸时，原来的初始三段和实际范围不变，ZG、ZD 就保持。插件也没有把两个框自动合成更高一层框的开关；延长原框、寻找下一个框和重新计算数据，分别处理。

## 5. 显示状态与重新计算怎样区分？

中枢矩形没有单独的“已确认／待确认”标签，也不像笔、线段那样分实线和虚线。框画出来，表示这次计算已经找到一个满足条件的区间；以后数据或最初成员变了，仍可能重算。

前面说上下沿保持，是在最初三段和实际范围不变的情况下。如果实时更新改变了分型、笔或线段，或者补载、修订历史数据改变了成员范围，就要重新算矩形。具体会不会动，可以先看底下的线段有没有变，笔的更新过程见[这里](https://www.structguide.com/concept/stroke#confirmation)。

### 5.1 面板参数与周期范围

中枢图层默认打开，保存过设置后会沿用你的选择。关掉图层只把框藏起来，计算仍继续。面板没有单独的“连续重叠模式”，也没有合并两个框为另一层框的开关。

换笔模式、品种、周期、复权或历史范围后，用新结果看图。每个周期分别算，不自动建立跨周期的矩形嵌套关系。其他选项见[参数总览](https://www.structguide.com/faq/drawing-rules)。

## 6. 画线规则速查

| 核对项 | 插件的实现规则 |
| --- | --- |
| 初始输入 | 连续三条已确认线段；待确认线段不参与 |
| 每段范围 | 覆盖区间内原始 K 线实际高低价，并覆盖连接端点，不只看端点连线高度 |
| 区间公式 | ZG = min(H1, H2, H3)，ZD = max(L1, L2, L3)；仅 ZG > ZD 时通过区间检查 |
| 固定边界 | 初始三段及其实际范围不变时保持 ZG、ZD，不随后续极值扩大 |
| 成员归属 | 独立连接段不重复归属两侧；旧中枢第三构成段不复用为连接段 |
| 方向排列 | 根据前后区间的相对位置选择初始成员，不改变线段端点 |
| L0/L1 检查 | 使用实际区间极值；L1 须已确认且反向首尾连接，不能用待确认线段代替 |
| 返回处理 | 触边、进入按返回处理；穿过另一边界时转入反方向越界检查 |
| 停止延伸 | 合法 L1 未返回时停止旧区间延伸，再检查右侧窗口；不自动保证有新矩形 |
| 周期与图层 | 不同周期分别计算；关闭图层只隐藏矩形 |
| 显示状态 | 无独立确认标签；输入或成员范围改变后重新核对 |

查算式时，也顺便看看选的是哪三段、每段范围怎样取。输入选得不同，即使用同一个算式，也可能得到不同的框。

## 7. 常见问题

### 7.1 缠论中枢画线公式只用 min、max，就能复现插件的矩形吗？

还不够。先要选出符合条件的已确认线段，取出各段实际极值，再检查哪些能放进同一个框、连接段有没有重复计入。建议先看[区间取值](https://www.structguide.com/concept/central-zone#definition)，再看[成员选择](https://www.structguide.com/concept/central-zone#members)。

### 7.2 为什么三条线看起来重叠，却没有矩形？

先看三条是否都已确认，再看实际覆盖的高低价是否有带宽度的共同部分，最后看成员和窗口条件。图上连接线相交，未必说明原始 K 线的实际范围和成员条件都满足。这里也不能换成三条笔或待确认线段。

### 7.3 插件怎样延伸原矩形、识别后续矩形？

后面接上已确认线段，插件会继续更新成员和框的长度。只要最初三段及其实际范围没变，ZG、ZD 就保持，后面走得更宽也不直接改上下沿。

旧框停下来以后，还要等后面的三段窗口和成员条件都满足，才会画下一个框。插件不会自动把两个框合成另一层，具体过程见[延伸处理](https://www.structguide.com/concept/central-zone#extension)。

### 7.4 为什么极值超出区间，上下沿没跟着移动？

因为上下沿取的是最初三段的共同区间，后面的极值不会直接替换它。若最初成员或它们的实际范围变了，才需要按[重算说明](https://www.structguide.com/concept/central-zone#confirmation)再算。

### 7.5 为什么矩形结束在确认发生之前？

框画到最后一个成员那里，后面又等到已确认线段，才知道原框该停止延伸。所以右边缘的位置，和取得停止依据的时间，可能隔着一段。

### 7.6 为什么新数据出现后，历史矩形也变了？

可以先看底下的线段有没有变化，再看最初三段、后面加入的成员及各段实际极值。如果历史范围、笔模式、周期或复权也换了，就已经不是同一组输入。

### 7.7 不同画线公式或软件的中枢不同，怎样比较？

先把数据范围、显示时点和笔模式对齐，再比线段和各段实际高低价。笔或线段已经不一样时，先从那里找差别，最后再比 ZG、ZD，见[画线差异核对顺序](https://www.structguide.com/faq/chanlun-indicator#drawing-differences)。

比较公式或软件时，名称里的“变体”“改进”帮不上具体比较，还是要看它怎样选线段、怎样取范围。这里记录的是插件的画法。

### 7.8 价格超出矩形时，插件就停止延伸吗？

不会。先有已确认的越界线段 L0，再看后面接上的反向已确认线段 L1。L1 没回来，才满足停止延伸条件；触边或进入算返回，穿过另一边则换方向继续检查。

如果只看到价格出了框，可以继续往后找 L1，再判断旧框是否停止、后面是否有条件画新框。位置关系可以对照[这张图](https://www.structguide.com/concept/central-zone#l1-相对区间的四种位置)。
