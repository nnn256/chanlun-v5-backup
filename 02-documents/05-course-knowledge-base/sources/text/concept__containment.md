# 缠论K线包含关系与合并图解：处理规则、公式与方向

Struct Guide 缠论助手（以下简称插件）处理包含关系时，可能把两根相邻 K 线当成一项来计算，原图上的两根柱子仍然保留。这一步发生在分型识别之前，下面用几组数字，把插件怎样合并、怎样选方向画出来。

如果你想找“向上取高高、向下取低低”具体怎么取，可以直接看[合并图解](https://www.structguide.com/concept/containment#merge)；想知道图上的标记为什么偏左，就看[价格来源](https://www.structguide.com/concept/containment#after-merge)。需要快速查条件时，文末还有[规则速查表](https://www.structguide.com/concept/containment#implementation)。

## 1. 什么样的两根K线构成包含？

先看一根 K 线从最低价到最高价占了多大范围。下面都按 [最低价, 最高价] 记，比如 [10, 18] 就是最低10、最高18。

上下影线也算在里面。 看的是整根 K 线的最高价和最低价，光看实体会漏掉范围。

在插件里，相邻两根 K 线只要一根完全罩住另一根，就会合并处理。也就是外面那根的最高价不低于里面那根，最低价不高于里面那根。高点相同、低点相同，甚至两端都相同，也算包含。

例如：

- A 的最高价是 18，最低价是 10，范围为 [10, 18]。

- B 的最高价是 16，最低价是 12，范围为 [12, 16]。

B 从12到16，整个落在 A 的10到18里面，所以是 A 包含 B。如果把 B 换成 [9, 19]，范围更大的就成了 B，这时是 B 包含 A。

再看高点相同的例子：A [10, 18]、B [12, 18]。上面都到18，B 的下面只到12，仍然被 A 罩在里面，插件也会合并。

## 2. 为什么先处理包含，再找分型？

插件接下来要比较三根标准 K 线。这里的标准 K 线，是合并后留下的高低价记录；网页上的原始柱子仍然保留。

仍看 A [10, 18] 和 B [12, 16]：A 的高点比 B 高，低点又比 B 低。两根的高低关系交叉了，插件会先把它们合成一个区间，再往下比较。

相邻包含处理完，插件才从留下的序列里取连续三根，比较中间这根的高低点。三根怎样比，可以接着看[分型识别规则](https://www.structguide.com/concept/fractal#definition)。

所以，想对照插件的分型标记，要先看它合并后用了哪三根。直接数原图上的柱子，可能会数到另一组。

## 3. K线合并公式：两根怎样变一根？

方向选好后，高点和低点分别取值。用 H1、H2 记两项的最高价，L1、L2 记最低价，具体取法如下：

| 合并方向 | 新的最高价 | 新的最低价 |
| --- | --- | --- |
| 向上合并 | max(H1, H2)，取较大值 | max(L1, L2)，取较大值 |
| 向下合并 | min(H1, H2)，取较小值 | min(L1, L2)，取较小值 |

表里的“向上／向下”只说明合并时怎样取值，不表示对行情的判断。

仍用 A [10, 18] 和 B [12, 16]：

- 向上合并：最高价取 max(18, 16) = 18，最低价取 max(10, 12) = 12，结果为 [12, 18]。

- 向下合并：最高价取 min(18, 16) = 16，最低价取 min(10, 12) = 10，结果为 [10, 16]。

包含处理：高低价怎样合并合并方向先按前置数据确定。相同的包含输入，在向上和向下两个独立示例中分别得到不同区间。

## 4. 合并方向怎么判断：何时向上，何时向下？

插件从左往右读 K 线，读一根，处理一根。走到包含的位置时，左边已经留下的记录，可能是单根 K 线，也可能是前面几根合并后的结果。

- 读入第一根时直接保留，不需要合并方向。

- 读入下一根后，先检查它与左项是否包含；不包含就直接保留两项，也不需要合并方向。

- 只有发现包含时，才为这一对确定方向并合并；合并后继续检查相邻项。

### 4.1 有前置参照时

看下图，A、B 是准备合并的两项。先往 A 左边看一格，找到已经留下的 P：比较 P 和 A，就能决定 A、B 怎样合并。 这时 A、B 还没合在一起，P 则可能已经合并过。

| 左项与参照的比较 | 插件采用的合并方向 |
| --- | --- |
| 最高价、最低价同时严格抬高 | 向上 |
| 最高价、最低价同时严格降低 | 向下 |
| 未满足上述两项 | 比较最高价：左项不低于参照时取向上，否则取向下 |

通常，P 和 A 的高低点会一起抬高，或者一起降低，对应表中前两行。如果两项都没满足，代码会再比较最高价，按第三行处理。

把数字放进去看：P 是 [5, 15]，A 是 [10, 18]，B 是 [12, 16]。A 比 P 的上面高了、下面也高了：18 > 15，10 > 5，所以 A、B 向上合并，得到 [12, 18]。

如果左边的 P 换成 [13, 21]，A、B 不变，这次就是18 < 21、10 < 13，A 的高低点都比 P 低，于是向下合并，得到 [10, 16]。

![方向怎样判定：先比较参照 P 与包含对左项 A](https://www.structguide.com/assets/images/rules/containment-direction.svg)

方向怎样判定：先比较参照 P 与包含对左项 A两组例子的 A、B 相同，只有前置参照不同。方向仅为合并取值方式，不能根据 A、B 的大小任意选择。

### 4.2 序列开头没有参照时

数据刚开头，左边还没有 P 怎么办？插件先比较左右两项的 (最高价 + 最低价) ÷ 2：

- 右项均值高于左项，取向上；低于左项，取向下。

- 均值相同，再比较收盘价：右项收盘价不低于左项时取向上，否则取向下。

比如 A [10, 18]、B [12, 16]，两项均值都是14，要继续看收盘价。A 收13、B 收15，就向上合并；A 收15、B 收13，就向下合并。这是插件处理序列开头的固定做法，面板里没有单独选项。

## 5. 处理之后，图上发生了什么？

### 5.1 计算序列可能变短，原始K线不变

合并一次，计算时就少一项。比如100根原始 K 线，处理后可能剩80根标准 K 线，具体会少多少，要看这组数据里有多少包含。

页面上仍能看到全部原始 K 线。看分型时要数合并后留下的标准 K 线，两边的数量可能不同。

### 5.2 插件会继续检查相邻包含

读入新的一根后，如果它与左边一项包含，先合并。合完再往左看一项，仍然包含就继续合；这一轮处理完，才接着读下一根。

这样留下的一项，可能来自好几根原始 K 线。重新加载历史数据，或最后一根 K 线更新后，这些分组也可能重新组合。

### 5.3 标记映射到合并后价格的原始来源

画顶分型标记时，插件会回头找：合并后这个最高价，原来是哪根 K 线给的？底分型则找最低价来源。比如向下合并后最高价取16，就找原始最高价为16的那根，而不是整组里最高的那根。

如果好几根都给出了同一个价格，就用最早的那根。因此，标记有时会落在合并组靠左的位置。

## 6. 画线规则速查

| 核对项 | 插件的实现规则 |
| --- | --- |
| 相等边界 | 最高价相同或最低价相同计入包含，两端相同也计入 |
| 不包含 | 两项最高价与最低价同时严格抬高，或同时严格降低；仅有区间重叠不构成包含 |
| 方向参照 | 逐根处理，遇到包含对 A、B 时，用 A 左侧已保留的相邻项 P 与 A 比较，再合并 A、B |
| 序列开头 | 无参照时先比较高低价均值，均值相同再比较收盘价 |
| 连续处理 | 合并后回查左侧相邻项，完成检查后继续读入后续原始 K 线 |
| 价格来源 | 高、低价分别对应回原始 K 线；并列的对应价格取最早来源 |
| 分型比较 | 高低价均严格比较；中间项与任一侧对应价格相等时，不满足相应分型条件 |
| 是否可关闭 | 包含处理没有独立关闭选项；显示图层的开关不改变这一步计算 |

如果和其他软件的结果不同，可以先从表里找相等价格、开头方向、连续合并和价格来源这几处差别，再看数据范围是否一致。更完整的步骤见[画线差异核对顺序](https://www.structguide.com/faq/chanlun-indicator#drawing-differences)。

## 7. 常见困惑

### 7.1 包含处理会修改行情网站的原始K线吗？

不会。网页上的原始 K 线仍然保留，插件不会把蜡烛图换成合并后的柱子。它用合并结果计算分型、笔等结构，再把标记放回原图。想看合并结果是什么样，可以看[区间示意图](https://www.structguide.com/concept/containment#merge)和[标记来源图](https://www.structguide.com/concept/containment#after-merge)。

### 7.2 核对分型时，该看原始K线还是标准K线？

看图上的价格时，还是看网站原始 K 线。想弄清一个分型标记为什么出现，就看插件合并后用了哪三根标准 K 线，再找到它们在原图上的价格来源。

### 7.3 包含关系需要自己判断或手动合并吗？

不用手动合并。插件读取数据后会自动完成这一步，再继续画分型、笔、线段和中枢。下面的例子是为了方便你看懂标记为什么画在这里。

### 7.4 为什么高点或低点相同也会被合并？

因为合并时相等也算包含；到了分型比较，相等又不通过。这两步对等号的处理不同。

### 7.5 不同软件的包含处理结果一样吗？

不一定。各软件对相等价格、序列开头、连续合并和价格来源的处理可能不同。先把数据范围对齐，再比较这些具体做法。

### 7.6 K线包含关系算上下影线吗？

算，比较的是整根 K 线的最高价和最低价，影线也在范围里。开盘、收盘价只在特定步骤用到：比如序列开头的均值相同时，还要用收盘价选方向，见[开头的方向选择](https://www.structguide.com/concept/containment#序列开头没有参照时)。

### 7.7 是前一根包含后一根，还是后一根包含前一根？

两种都算。范围大的可以在左，也可以在右。但谁包住谁，不能直接决定向上还是向下合并，还得看[左边的参照](https://www.structguide.com/concept/containment#direction)。

### 7.8 “包含再包含”和顺次处理，结果一定一样吗？

要看是不是按同样的顺序合。插件每读入一根，先处理它与左项的包含，再回查左边，处理完才读下一根。如果先挑几根分组合并，再合各组结果，就换了一套顺序。

顺序一换，当时拿来判断方向的参照也可能变。遇到结果不一致，可以从第一处合并开始，看看方向怎么选、合完有没有回查、价格来自哪根，见[连续处理说明](https://www.structguide.com/concept/containment#工具会继续检查相邻包含)。
