# 走势类型递归、中枢背驰与真实多周期触发 V2

本次新增可运行入口[run_v2.py](run_v2.py)，规则模块位于[chanmodel/v2](chanmodel/v2)。旧版批量结果保持其生成版本的语义，不用新版名称覆盖旧统计。

## 已落地的三层

| 环节 | V2行为 | 证据与状态 |
| --- | --- | --- |
| 走势类型递归 | L0是已确认线段的显式最低边界；L1以上构造已完成盘整类型，上一层只接收完整、连续、同rank的下级类型 | `components`、`center_ids`、`completion`、`completed_at`、`pending_tail_ids` |
| 严格中枢条件 | 核验三个连续次级别类型均已完成，以实际区间交集固定ZG/ZD；形成时间取三者完成时间最大值 | 中枢谓词审计通过或报错，缺条件不冒充完整中枢 |
| 趋势与背驰 | 同rank中枢外围范围分离、明确比较段A/C、同向同层、新极值、离开与不返回；再看MACD辅助衰减和零轴条件 | 每个gate及失败原因独立输出；力度衰减不能单独建立趋势 |
| 真实周期校验 | 显式证券、周期、复权、收盘时间；检查分钟原生间隔、OHLCV聚合、完整子级窗口、重复输入 | 数据不合则`blocked_data_contract`，不继续产生触发 |
| 下级确认 | 查找末端区间内同一价格拐点、已完成下级走势，以及反向中枢离开后不返回的结构证据 | `waiting_lower_confirmation`或保存具体类型/中枢/离开/回试ID |
| 触发器 | 确认之后，更细周期出现新的合法确认笔；核对时序，并用更细数据持续检查父候选失效边界 | `waiting_trigger`、`structurally_triggered_under_profile`或`invalidated` |

同一份日线分别命名为day、30m、5m的已知错误已在新入口和旧`multilevel`入口拦截。新版还会拒绝有正确列名但OHLC聚合不符、证券不同或复权不同的数据。

## 两种“完成”必须区分

原文17、18、63课给出中枢与走势类型递归，38课讨论固定级别的同级别分解。V2采用明确配置的`same_level_completed_center_cut_v1`：满足中心、连续性和完整下级输入后，形成可以向上递归的盘整分解单元。其`completion.is_turn_confirmation=false`，不表示市场已经反转。盘整的首末子级方向与净价格位移也分列，扩张形态不能用净涨跌简单否决。

另外独立计算`opposite_center_break_completion_v1`视图：已有中枢被反方向离开，并由完成的回试证明不返回时，才确认这条视图的结束。具备两个以上同方向、外围严格分离中枢的视图命名为趋势；无法证明的扩张、前缀和尾部保持pending。触发器读取这类反向破坏凭据，**不会把仅完成的分解单元当反转**。

这是一个明确、可检验的分解与确认规范。它没有声称证明原著所有可能分解、全部争议边界或唯一性；基础线段仍继承当前经过测试的工具规则。`strict_original_equivalence_proven=false`表示该整体命题尚未证明，不表示所有新模块都是空壳。

## 运行

在本目录使用已归档的真实TDX数据：

```powershell
python run_v2.py analyze --symbol sz000001 --period day --cutoff 2026-11-06T02:03:45+08:00 --output runs/v2/my-day.json
python run_v2.py multiframe --symbol sz000001 --cutoff 2026-11-06T02:03:45+08:00 --output runs/v2/my-multiframe.json
```

默认核对价格容差0.005元、成交量容差1股。真实TDX不同周期中可出现按手取整的量差；若研究决定允许明确的绝对差额，可显式写入参数，报告会保留实际差值和阈值：

```powershell
python run_v2.py multiframe --symbol sz000001 --volume-tolerance-shares 1000 --cutoff 2026-11-06T02:03:45+08:00 --output runs/v2/my-multiframe-tolerance.json
```

不能把阈值调整解释为数据本来完全相等。此次平安银行默认1股容差报告220个日线/30分钟窗口、3个30分钟/5分钟窗口的量差；样本OHLC一致。显式1000股容差后，两层数据契约通过。

也可从实际5分钟行情严格聚合30分钟与日线。仅使用子K线齐全的窗口，缺失窗口保持缺失：

```powershell
python run_v2.py multiframe --symbol sz000001 --derive-from 5m --volume-tolerance-shares 0 --cutoff 2026-11-06T02:03:45+08:00 --output runs/v2/from-observed-5m.json
```

派生数据来自实际行情，不是合成价格；其可用历史只能覆盖最细周期源的范围，不能恢复更早的日线。

## 独立CSV与来源凭据

```powershell
python run_v2.py analyze --symbol sh600000 --period day --csv input.csv --metadata input-metadata.json --source tdx --adjustment unadjusted --cutoff 2026-11-05T15:00:00+08:00 --output result.json
```

CSV要求`closed_at,open,high,low,close`，有明确时区，可带volume/is_closed。压缩`.csv.gz`可直接读取。来源metadata存在时，检查symbol、period、adjustment、source和CSV哈希；缺metadata时明确标为调用者声明，不声称已认证证券身份。严格多周期OHLCV核验缺volume会阻断，不把缺值补零。

## 背驰与六类点

趋势背驰必须同时具有两个分离的同rank中枢、此前中枢位于A之前、完成的同向A/C、C创新极值、相应离开与不返回结构。MACD只提供辅助力度；数值化“接近零轴”采用比较A段尺度的明确阈值，原文24课并未给出唯一常数，因此这一阈值是研究约定。

没有同级趋势上下文的衰减记为盘整力度变化，不产生严格一类结论。二类点检查一类候选之后的首次反弹/回试，101课的弱回试需另有明确命名的力度比较，不能只开一个开关。三类点核对中枢、离开、首次合格回试和不返回；当前边界规范明确采用触边返回。

原文53课中不依赖同级一买的某些小转大二买形式、本规范之外的分解习惯、最优即时拐点等仍不属于已证实现范围。所有点仍需下级确认和触发，不把指标Gate通过直接转成交易指令。

## 回放与时间

单序列参考回放：

```powershell
python run_v2.py replay --symbol bj920002 --period day --cutoff 2026-11-06T02:03:45+08:00 --output runs/v2/replay.json --events runs/v2/events.jsonl
```

`chanmodel.v2.engine.replay_multiframe`接受明确的最细级别收盘时间序列，逐截止点重新截取数据、核对契约并运行触发状态机。若只选择部分截止点，必须称为该时间表的参考回放，不能声称每分钟都已重跑。

`completed_at/available_at`记录结构在前序边界已知后的可用位置；后一段不能早于前一段边界确认，自己的原始依据时间另存`raw_basis_at`。事件的`observed_at`记录实际首次看到该版本的时刻。更早的价格端点不回填为更早已知。原事件不会因后来的确认或划分修改而被覆盖。

## 本次验证

- 真实沪深京6股：CSV/来源哈希、递归中心及类型凭据逐对象重算；实际周期聚合检查；不满足触发的保持等待/历史不足/失效。
- 平安银行日线：递归L1/L2/L3分别形成31、10、3个完成分解单元；67个中枢凭据、44个类型凭据复核通过。
- 同一份日线换三种周期名：新版输入契约及旧入口均拒绝。
- 真实日线500/600根前缀：旧事件完全一致；150/300/500/600截止点的直接计算与回放结果一致。
- 从真实5分钟聚合：493个日线窗口、3944个30分钟窗口在零成交量差容差下核对通过。
- 正向触发测试从真实规则构造的下级反向中枢破坏开始，再加入确认之后的新细级笔；早到、未确认或价格不匹配的证据均被拒绝。

详细机器证据：[real-validation.json](artifacts/recursive-v2-20261107/real-validation.json)。完整测试数量和退出码见交付核验记录。

这次没有重跑并替换先前5578股全历史批次；旧结果继续属于旧模型版本。V2是新规则版本，若用于批量比较，应新建run保存两个版本，不能沿用旧模型绩效数字。
